# تدقيق إتاحة Flutter

**النوع:** مهارة داخلية خاصة بالمشروع.

## مراتب السلطة

1. طبّق `AGENTS.md` وقرارات المشروع أولًا.
2. اقرأ `docs/design/UX_UI_SPEC.md` والقسم المنطبق من
   `technical/FINAL_CROSS_CUTTING_UX_ARCHITECTURE.md`.
3. استخدم `well-android-ui` و`m3-expressive` للقيم والمكوّنات، والمعايير
   الرسمية للإتاحة عند قرار جديد.
4. شغّل `npm run c:state` مرة واحدة فقط إن لم يكن قد شُغّل.

## التدقيق البرمجي

### الدلالة والتنقل

- كل فعل icon-only يحمل `Semantics`/tooltip باسم عربي يصف الفعل لا شكل الرمز.
- لا تكرر قارئ الشاشة النص نفسه من الأب والابن.
- ترتيب القراءة يطابق RTL والمنطق البصري.
- العناصر الزخرفية مستبعدة من semantics.
- الحالة الديناميكية المهمة معلنة بطريقة مناسبة ولا تقاطع المستخدم بإفراط.
- Back وتبديل البئر لا يهدمان عملًا حرجًا بصمت.

### البصر واللون

- النص العادي يحقق التباين المطلوب، والنص الكبير يقاس بحجمه الفعلي.
- المعنى المالي أو حالة المزامنة = نص + رمز/بنية؛ اللون وحده غير كافٍ.
- focus indicator مرئي ولا تحجبه عناصر ثابتة.
- لا تستعمل لون العلامة بوصفه لون نجاح تلقائيًا.

### الحركة واللمس

- كل هدف تفاعلي Android لا يقل عن 48×48dp.
- لا فعل حرج يتطلب gesture فقط.
- الحركة لا تمنع الوصول إلى المحتوى وتحترم تقليل الحركة حيث يمكن.
- حالات الضغط والتحميل والتعطيل مميزة دلاليًا وبصريًا.

### النص وRTL

اختبر 1.0 و1.3 و2.0 على الأقل، ومع أسماء ومبالغ طويلة:

- لا قص لنص حرج أو تراكب أو overflow.
- لا تصغير خط لإخفاء المشكلة.
- استخدم directional properties بدل left/right.
- الأرقام 0-9 ثابتة والنص المختلط يأخذ اتجاهًا محليًا عند الحاجة.

## الاختبارات

- أضف Widget tests لـSemantics والأهداف والحالات التي يمكن قياسها بثبات.
- استخدم `tester.ensureSemantics()` وfinders الدلالية عند ملاءمتها.
- لا تجعل Golden test بديلًا عن Semantics أو TalkBack.
- شغّل الاختبار المستهدف ثم `flutter analyze` و`flutter test` عند التعديل.
- TalkBack والتركيز الفعلي وقراءة النص تحتاج قبولًا على جهاز/محاكي؛ إن لم
  تُشغّل فسجّل NOT RUN.

## التقرير

لكل نتيجة: المستخدم المتأثر، الخطوة، السلوك الحالي، معيار المشروع/المنصة،
الإصلاح الأدنى، وكيف نختبره. رتّب الأولوية: حاجز يمنع إتمام مهمة، ثم تضليل
حالة مالية/مزامنة، ثم صعوبة، ثم تحسين.

## توافق الوكلاء

- **ZCode:** يمكن دمج الفحص مع `android-dev` وشجرة UI ولقطات الجهاز.
- **Claude Code:** استخدم أدواته المكافئة أو بروتوكول اختبار يدوي؛ لا تفترض
  MCP خاصًا بـZCode.
- أبقِ `ui-ux-pro-max` و`well-android-ui`؛ هذه المهارة بوابة إتاحة وليست
  بديلًا عن الهوية أو التصميم.

## بوابة ما قبل التسليم

- [ ] فُحص Semantics لا الصورة فقط.
- [ ] اختُبر RTL وتكبير النص والنص الطويل.
- [ ] أهداف اللمس والحالات غير اللونية مفحوصة.
- [ ] فُصل الفحص الآلي عن TalkBack الفعلي.
- [ ] لا ادعاء «متاح بالكامل» مع حالات NOT RUN.
- [ ] نتائج الاختبار المعروضة شُغّلت فعلًا.
