# قبول التطبيق على جهاز Android

**النوع:** مهارة داخلية خاصة بالمشروع.

## قواعد البدء

1. اقرأ `AGENTS.md` و`RESUME_POINT.md` والوثيقة التقنية للمسار الجاري.
2. شغّل `npm run c:state` مرة واحدة إن لم يكن قد شُغّل.
3. حدّد هل الهدف Emulator أم جهاز حقيقي؛ لا تساوي بين دليليهما.
4. لا تنشئ AVD، ولا تقبل رخص SDK، ولا تمسح بيانات جهاز دون موافقة صريحة.
5. لا تستخدم بيانات إنتاج أو حسابًا ماليًا حقيقيًا في سيناريو قبول.
6. نجاح Widget test لا يثبت Android background behavior.

## مصفوفة القبول

وثّق لكل حالة: نوع الجهاز، API level، نسخة التطبيق، حالة الشبكة، إعداد
البطارية، خطوات التنفيذ، النتيجة، screenshot/log مقتضب، وما لم يُختبر.

### دورة حياة التطبيق

- إغلاق واجهة التطبيق ثم فتحها.
- قتل العملية أثناء جلسة جارية ثم استعادتها من التخزين المتين.
- إعادة تشغيل الجهاز والتحقق من عدم فقد Outbox أو active projection.
- Force Stop حالة منفصلة؛ لا تعد بعمل الخلفية بعده.

### الشبكة والمزامنة

- Offline كامل عند حفظ عملية ميدانية.
- عودة الشبكة وإرسال نفس Command ID.
- فقد الرد بعد وصول الأمر للخادم ثم retry دون أثر مكرر.
- خطأ عابر مقابل conflict يحتاج مراجعة.
- رفض الإشعارات لا يمنع حفظ البيانات أو مزامنتها.

### قيود Android

- Doze/Battery Optimization/Restricted mode حسب ما يمكن ضبطه بأمان.
- WorkManager لا Foreground Service دائم.
- لا تعتمد على رمز الشبكة دليلًا لوصول الخادم.
- سجّل التأخير المقاس بدل وصف «لحظي» بلا رقم.

### الواجهة الميدانية

- RTL أصلي والأيقونات الاتجاهية صحيحة.
- الأرقام 0-9 والمعرفات والمبالغ مقروءة.
- text scale مرتفع دون قص أو overflow.
- Touch targets لا تقل عن 48dp.
- Light/Dark contrast، ضوء الشمس قدر الإمكان، واستخدام بيد واحدة.
- TalkBack/semantics للمسار الحرج على جهاز أو محاكي يدعمه.

## سير ZCode

عند توفر `android-dev`:

1. نفّذ preflight ثم اكتشف المشروع والجهاز.
2. ابنِ وشغّل على serial محدد لتجنب تغيير الهدف بين الخطوات.
3. افحص شجرة الواجهة قبل النقر، ثم استخدم resolve/tap/type/swipe.
4. التقط screenshots وlogcat محدودًا حول الفشل.
5. أوقف عند خطوة قد تمسح بيانات أو تغير إعدادًا عالي الأثر.

## سير Claude Code

استخدم أدوات Android/ADB المتاحة له بالخطوات نفسها. إن لم تتوفر أتمتة UI،
أنشئ بروتوكول اختبار يدوي للمالك مع مواضع حفظ الأدلة. لا تحذف أو تعدّل
مهارة `android-dev` الخاصة بـZCode، ولا تفترض وجودها داخل Claude Code.

## نتيجة القبول

استخدم واحدة لكل سيناريو: PASS، FAIL، BLOCKED، NOT RUN. لا تحوّل BLOCKED
بيئيًا إلى FAIL في التطبيق ولا إلى PASS. «مقبول على Emulator» لا تعني
«مقبول على جهاز حقيقي».

## بوابة ما قبل التسليم

- [ ] البيئة والجهاز ونسخة التطبيق مسجلة.
- [ ] كل نتيجة لها دليل وخطوات قابلة للتكرار.
- [ ] اختُبرت المتانة بعد process death لا RAM فقط.
- [ ] فُصل Local Success عن Server ACK.
- [ ] لم تُعمم نتيجة Emulator على جهاز حقيقي.
- [ ] التقرير بالعناوين الأربعة وحالة ما لم يُشغّل صريحة.
