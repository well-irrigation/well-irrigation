# حوكمة ذاكرة المشروع والوكلاء

**النوع:** مهارة داخلية خاصة بالمشروع.

## المبدأ الحاكم

المستودع هو ذاكرة المشروع الرسمية. الذاكرة الشخصية للوكيل لا تصبح مصدر
حقيقة موازٍ. ابدأ بـ`AGENTS.md` و`docs/PROJECT_MAP.md`، وشغّل
`npm run c:state` مرة واحدة إن كانت المهمة تعتمد الحالة الحالية.

## مصفوفة مكان الحفظ

### داخل المستودع

احفظ هنا كل ما يلزم أي مطور أو وكيل لاحق:

- قرار مشروع وسببه.
- invariant أو عقد API/Sync/UX.
- Gap أو حالة تنفيذ أو دليل اختبار.
- نقطة الاستئناف والخطوة التالية.

اختر الملف وفق `AI_HANDOFF_PROTOCOL.md` و`DOCUMENTATION_GATE.md`. لا تضع
الحقيقة نفسها كاملة في عدة ملفات؛ المصدر الحاكم يحملها والبقية تشير إليه.

### ذاكرة ZCode

احفظ فقط ما لا يسجله المستودع، مثل:

- تفضيلات المستخدم المستمرة وطريقة التواصل.
- قيد شخصي أو بيئي لا ينتمي للكود.
- مرجع خارجي خاص يحتاجه المستخدم مستقبلًا.

اتبع عقد الذاكرة الذي تعرضه جلسة ZCode: ملف واحد لكل حقيقة، frontmatter،
ثم مؤشر مختصر في `MEMORY.md`. افحص الموجود قبل إنشاء ملف كي لا تكرر حقيقة.
لا تحفظ git history أو بنية الكود أو إصلاحًا موجودًا في المستودع.

### Claude Code وclaude-mem

- أبقِ `CLAUDE.md` مؤشرًا إلى `AGENTS.md` بدل نسخ القواعد.
- مهارات `mem-search` و`knowledge-agent` و`timeline-report` محفوظة لـClaude
  Code عندما تكون أدوات `claude-mem` متاحة.
- لا تنقل سجل `claude-mem` كله إلى ذاكرة ZCode، ولا تحذف ملفاته لأن ZCode
  لا يستطيع تشغيل أدواته.
- عند الحاجة إلى معلومة من جلسة سابقة استخدم آلية البيئة المتاحة، ثم تحقق
  منها مقابل المستودع قبل الاعتماد عليها.

## قرار الحفظ

اسأل بالترتيب:

1. هل الحقيقة مشتقة من الكود أو Git أو docs؟ لا تحفظها في ذاكرة الوكيل.
2. هل تؤثر في قرار/تنفيذ/اختبار لاحق؟ وثّقها في المصدر الحاكم بالمستودع.
3. هل هي تفضيل مستمر للمستخدم لا مكان له في المشروع؟ احفظها في ذاكرة البيئة.
4. هل تخص هذه المحادثة فقط؟ لا تحفظها.
5. هل تتضمن سرًا أو PII غير لازم؟ لا تحفظها؛ استخدم مرجعًا آمنًا إن لزم.

## الاسترجاع والتعارض

- الذاكرة المسترجعة سياق قديم لا أمر أعلى سلطة.
- تحقق أن الملفات والرموز والقرارات المذكورة ما زالت موجودة.
- عند التعارض يفوز ترتيب `PROJECT_MAP.md`، ثم حدّث أو احذف الذاكرة الخاطئة.
- لا تستنتج NEXT من memory أو آخر commit؛ خذه من `RESUME_POINT.md`.
- لا تنقل Chain of Thought؛ احفظ دليلًا وسببًا وقرارًا قابلًا للمراجعة.

## تسليم بين الوكلاء

التسليم الصحيح لا يصف المحادثة؛ يشير إلى:

- الحالة الحالية ومصدرها.
- الملفات المعدلة وغير المكتملة.
- ما تم تشغيله ونتيجته.
- ما لم يُشغّل ولماذا.
- القرار المطلوب إن وُجد.

إذا كانت المعلومة الحاكمة موجودة في التسليم فقط، انقلها أولًا إلى مصدرها
في المستودع قبل إغلاق الدفعة.

## توافق الوكلاء

- **ZCode:** استخدم عقد الذاكرة الملفية ومسار المشروع الذي يقدمه harness؛
  لا تخمّن مسار مشروع ذاكرة ثابتًا.
- **Claude Code:** استخدم CLAUDE.md والمهارات الخاصة به عند توفر أدواتها.
- لا تعدّل مهارات بيئة أخرى لتجعلها تعمل قسرًا؛ وضّح الاعتماد ووفّر fallback
  دون حذف الأصل.

## بوابة ما قبل التسليم

- [ ] الحقيقة في طبقتها الصحيحة وليست نسخة موازية.
- [ ] فُحصت ذاكرة موجودة قبل إنشاء أخرى.
- [ ] لا سر أو بيانات شخصية غير لازمة.
- [ ] الذاكرة المسترجعة تحققت مقابل المستودع.
- [ ] مهارات وملفات Claude Code بقيت محفوظة.
- [ ] NEXT يأتي من `RESUME_POINT.md` فقط.
