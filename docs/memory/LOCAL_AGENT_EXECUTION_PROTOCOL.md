# Local Agent Execution Protocol — بروتوكول الوكيل المحلي

**القرار الحاكم:** ق-128
**آخر تحديث:** 2026-09-15
**الحالة:** نافذ

## 1. الهدف

هذا الملف يحكم تفويض التنفيذ إلى وكيل ذكاء اصطناعي محلي
مع الحفاظ على رصيده وسياقه بأقصى قدر ممكن، دون تخفيض
جودة الإثبات أو تجاوز قواعد المشروع.

القاعدة:

> التوفير يأتي من منع التكرار والاستكشاف غير اللازم،
> لا من تقليل التحقق.

ق-121 يبقى حاكمًا لاستهلاك الجولة، وهذا البروتوكول
يفصّل تطبيقه عند وجود وكيل محلي منفذ.

## 2. نموذج العمل الثلاثي

الأدوار منفصلة بين المالك والمهندس الرئيسي والوكيل المحلي.

### المالك

- صاحب القرار النهائي.
- ينفذ الأوامر المحجوزة للمالك.
- ينفذ أوامر التوثيق الجاهزة التي يسلمها المهندس الرئيسي.
- لا يحتاج كتابة التوثيق يدويًا.

### المهندس الرئيسي

- يحدد المعمارية ونطاق الجولة.
- يكتب Prompt الوكيل المحلي.
- يحدد مصادر الحقيقة والثوابت.
- يراجع نتيجة التنفيذ.
- يحدد ما يحتاج توثيقًا.
- يصيغ أوامر التوثيق الجاهزة للمالك.

### الوكيل المحلي

- منفذ كود محدود النطاق فقط.
- يقرأ أقل قدر لازم.
- يعدل الملفات المصرح بها فقط.
- يشغل الفحوص المسموحة.
- يعيد تقريرًا مختصرًا ودقيقًا.
- ليس مصدر قرار أو توثيق مستقلًا.

## 3. STRICT TOKEN ECONOMY MODE

كل جولة محلية تبدأ افتراضيًا بهذا الوضع:

1. هدف واحد قابل للقياس لكل جولة.
2. وكيل واحد فقط.
3. لا Subagents إلا بطلب صريح من المالك.
4. يحدد مستوى التفكير مسبقًا: LOW أو MEDIUM أو HIGH.
5. لا مسح شامل للمستودع إذا كان موضع العمل معروفًا.
6. لا قراءة ملفات كاملة إذا كفى بحث أو مقطع محدد.
7. لا إعادة قراءة الملف نفسه دون سبب جديد.
8. لا إعادة اكتشاف حقيقة زوده بها المهندس الرئيسي.
9. لا بحث خارجي إلا إذا طلبه Prompt صراحة.
10. لا Plan مطولة ولا سرد للعمل أثناء التنفيذ.
11. لا Logs كاملة في التقرير النهائي.
12. لا إعادة فحص ناجح إذا لم يتغير ما يؤثر فيه.

تقليل الرصيد لا يبرر حذف اختبار أو Guard لازم.

## 4. بناء الجولة

كل Prompt تنفيذي يحدد صراحة:

- MODE
- SESSION PRECHECK
- SOURCE OF TRUTH
- OBJECTIVE
- READ FIRST
- READ ONLY IF NEEDED
- ALLOWED TO MODIFY
- DO NOT MODIFY
- IMPLEMENTATION CONTRACT
- VERIFY
- STOP CONDITIONS
- FINAL RESPONSE

الهدف يكون واحدًا وضيقًا وقابلًا للتحقق، ولا يعطى الوكيل
مهمة مفتوحة من نوع: أصلح المجال كاملًا.

## 5. حدود القراءة

- READ FIRST تحتوي أقل مجموعة ملفات لازمة.
- READ ONLY IF NEEDED لا تقرأ إلا لسبب محدد ظهر أثناء الجولة.
- إذا كان الرمز أو الملف معروفًا يستخدم بحثًا مستهدفًا.
- لا يعاد استكشاف حقائق أعطاها المهندس الرئيسي كحقائق مثبتة.
- لا يدعي الوكيل استخدام أداة غير متاحة فعليًا.

## 6. حدود التعديل

كل Prompt يحدد ALLOWED TO MODIFY صراحة.

محظور افتراضيًا تعديل:

- docs/**
- AGENTS.md
- CLAUDE.md
- ملفات الحوكمة.
- إعدادات النشر.
- أي ملف خارج نطاق الجولة.

إذا احتاج الحل ملفًا خارج القائمة يتوقف الوكيل ويبلغ BLOCKED.

## 7. الأوامر المحظورة على الوكيل المحلي

لا ينفذ الوكيل المحلي:

- git commit أو git push.
- Merge أو Merge Request.
- db:reset أو db:test.
- Docker verification.
- Cloud verification أو Cloud deployment.
- أي أمر يغير تاريخ المستودع.
- أي أمر محجوز للمالك في AGENTS.md.

## 8. التوثيق

الوكيل المحلي لا يكتب ولا يعدل التوثيق.

بعد التنفيذ يعيد DOC NOTES مختصرة فقط.
المهندس الرئيسي يراجع النتيجة ثم يحدد الملفات المنطبقة
ويعطي المالك أوامر التوثيق الجاهزة وفق Documentation Gate.

## 9. التحقق

التسلسل المعتاد للجولة:

تعديل محدود → فحص مستهدف → c:app عند انطباقه → تقرير مختصر
→ مراجعة المهندس الرئيسي → فحوص المالك الأخرى عند الحاجة.

لا يشغل الوكيل كل الاختبارات بعد كل تعديل صغير بلا سبب.
لكن أي فحص لازم لإثبات صحة التغيير لا يسقط لأجل تقليل الاستهلاك.

## 10. شروط التوقف

يتوقف الوكيل فورًا ويعيد BLOCKED إذا:

- افتراض أساسي في Prompt غير صحيح.
- مصدر الحقيقة يناقض المطلوب.
- الحل يحتاج قرار Product أو Architecture جديدًا.
- الحل يحتاج Migration غير مصرح بها.
- الحل يحتاج ملفًا خارج نطاق التعديل.
- Worktree يحتوي تغييرًا غير متوقع.
- ظهر فشل خارج نطاق الجولة لا يمكن عزله بأمان.
- احتاج إلى فعل محظور في AGENTS.md.

لا يحاول حل المشكلة المجاورة من تلقاء نفسه.

## 11. تقرير الوكيل

التقرير النهائي يلتزم بالقالب التالي:

STATUS: PASS | BLOCKED | FAIL

CHANGED:
- الملفات فقط

WHAT:
- من نقطة إلى ثلاث نقاط فقط

VERIFICATION:
- الأمر → النتيجة

NOT RUN:
- ما لم يشغل ولماذا

DOC NOTES:
- بحد أقصى خمس حقائق

لا يعرض Chain of Thought ولا يعيد نسخ Prompt.

## 12. توزيع التفكير

- LOW: تنفيذ قرار محسوم أو تعديل ميكانيكي في موضع معروف.
- MEDIUM: إصلاح معروف يمتد إلى عدة ملفات مترابطة.
- HIGH: سبب مجهول أو مال أو صلاحيات أو تزامن أو قرار معماري.

المهندس الرئيسي يحلل مسبقًا ما يستطيع تحليله حتى لا
يستهلك رصيد الوكيل المحلي في إعادة التحليل.

## 13. قاعدة المصدر

المستودع يبقى ذاكرة المشروع الرسمية.
تقرير الوكيل المحلي دليل تنفيذ مؤقت وليس مصدر حقيقة دائمًا.
أي حقيقة تلزم جولة لاحقة تنتقل بعد التحقق إلى المصدر الصحيح
بواسطة دفعة التوثيق التي يديرها المهندس الرئيسي.

## 14. بوابة الجولة

قبل اعتبار جولة الوكيل ناجحة:

- الهدف المحدد تحقق.
- لم يتوسع نطاق الملفات بصمت.
- الفحوص اللازمة لها دليل.
- ما لم يشغل معلن.
- DOC NOTES سُلّمت.
- راجع المهندس الرئيسي النتيجة.

وقبل إغلاق الموضوع بالكامل:

- Documentation Gate مطبقة.
- Commit موجود.
- Push ناجح.
- Worktree نظيف.
