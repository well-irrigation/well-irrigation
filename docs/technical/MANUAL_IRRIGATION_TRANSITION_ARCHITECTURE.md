# عقد الانتقال إلى التشغيل اليدوي — ق-137

**التاريخ:** 2026-10-20 · **الحالة:** معتمد تصميميًا، غير منفذ أو مثبت بعد.

## الواقع الحالي

العمل المحلي يضم محرك تنفيذ مرتبطًا بجذر التطبيق مع توليد آثار آلية عند مرور الوقت أو استئناف التطبيق، وأجزاء مشتركة للاحتفاظ بعمليات الإكمال والتخزين والمزامنة والإشعارات. ملفات العمل المحلية غير مدمجة في GitHub؛ هذا العقد لا يغيّرها.

## العقد المستهدف

1. لا يؤدي مرور الوقت أو وصول تنبيه أو فتح التطبيق أو استئنافه أو اكتمال مزامنة إلى **إنشاء** بدء أو إنهاء أو انتقال حجز تلقائي.
2. يبدأ المشغل الجلسة وينهيها بإجراء بشري صريح مؤذن؛ تحمي القاعدة عدم التكرار والتدقيق والتزامن.
3. الجلسة التاريخية تحمل بداية ونهاية فعلية ومدة محسوبة، وتعديلها بأثر تصحيحي وسبب إلزامي لا محو للواقعة الأصلية.
4. الجلسة الجارية قد تكون بلا نهاية مخططة؛ يظهر الزمن المنقضي ويستمر حتى الإنهاء الصريح.
5. الحجز المستقبلي قد يكون بلا نهاية مخططة، ولا يجيز ذلك تداخلًا على البئر أو تشغيلًا ذاتيًا؛ سياسة حجز المورد والتعارض تتطلب تصميمًا واختبارًا قبل التنفيذ.
6. تبقى منظومة المال والديزل والمقدمات والدفعات وفواتير التسوية وصلاحيات API مرجعية خادمية، دون افتراض أن الإدخال غير المتصل أصبح مقبولًا ماليًا.
7. التنبيهات المحلية عمليات تذكير فقط؛ يمكن أن تعمل دون اتصال بعد جدولة محلية صحيحة، مع اختبارات إقلاع الهاتف والأذونات وتأخر التسليم.

## حدود الفصل والبيانات السابقة

- تُعزل مصادر إنشاء الأوامر التلقائية داخل `app.dart` و`offline_session_coordinator.dart` و`session_execution_runtime.dart` ومنطق المتابعة والانتظار، بدل حذف آليات الإنهاء اليدوي والاستعادة.
- لا يكفي حجب نوع أمر عام لأن عمليات البدء والإكمال اليدوية والتلقائية تتشارك النوع. قبل التفعيل يلزم مصدر نية موثوق ومخزن مع كل أثر، وسياسة معالجة آمنة للأوامر المؤجلة القديمة.
- إذا تعذر إثبات مصدر النية لأمر قديم، لا ينفذ أثرًا جديدًا دون مراجعة بشرية أو تسوية خادمية مؤمنة. لا تمحى سجلات التدقيق ولا يتم إيقاف جلسة تشغيل حقيقية بسبب تبديل الإعداد.
- يجب مراجعة وضع الهجرات السحابية/المحلية ومساواة العقد قبل نشر أي تغير. M114 محجوزة لغرضها الحالي.

## مراحل التنفيذ اللاحقة (ليست منجزة بهذا التوثيق)

1. تدقيق أوامر الانتظار والجلسات القديمة وتحديد سياسة انتقال واختبارات عدم التكرار/السباق.
2. فصل الأتمتة للعميل والخادم على نحو متسق؛ عدم انقطاع البدء/الإيقاف اليدوي والمزامنة.
3. تكملة الإشعارات دون اتصال وبعد إعادة التشغيل مع قبول هاتف حقيقي.
4. استكمال الحالات الثلاث والنهاية الاختيارية مع حارس تداخل البئر.
5. استكمال التصحيحات المدققة والدفعات والفواتير واختبارات المحاسبة.

## شروط القبول

- عند مرور الموعد أو استئناف التطبيق أو إعادة تشغيل الجهاز أو انقطاع/عودة الشبكة، لا ينشأ أي أمر بدء أو إنهاء تلقائي جديد.
- المراجعة تمنع إرسال أمر آلي محفوظ غير مأذون، ولا تمنع إعادة محاولة فعل يدوي مأذون.
- الإكمال والدفع لا يتكرران بعد انقطاع الاتصال وإعادة المحاولة والموت المفاجئ للتطبيق.
- مدة الجلسة الواقعية لا تستبدل بالموعد المخطط؛ التعديل المالي يترك أثرًا وتدقيقًا.
- تنبيه النهاية لا يساوي إكمال الجلسة؛ الصلاحيات والحالات الفارغة والأخطاء واضحة.
- نجاح فحوص الهاتف والقاعدة والقبول الحقيقي ونشر الهجرات لا يُدعى قبل أدلته.
