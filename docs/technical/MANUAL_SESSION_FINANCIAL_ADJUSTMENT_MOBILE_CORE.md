# اعتماد تعديل مبلغ جلسة — نواة الهاتف

**الحالة:** منفذ محليًا في نواة الهاتف دون واجهة مستخدم.
**عقد الخادم:** `MANUAL_SESSION_FINANCIAL_ADJUSTMENT_SERVER.md`.
**النطاق:** نماذج القراءة، الأمر المتين، النقل النوعي، والاستعادة بالإيصال أولًا.

## مصدر الحقيقة

الهاتف لا يحسب مبلغًا ماليًا ولا فرقًا ولا متبقيًا. يقرأ من الخادم، كحقائق
مستقلة، المبلغ الأصلي والنظامي والمعتمد والفعّال، والتسديد والمتبقي،
والمراجعات التشغيلية والنظامية واليدوية. القيم المسماة `_minor` في العقد
هي أعداد صحيحة بريالات يمنية كاملة، وتمثل في Dart بـ`int` دون ضرب أو قسمة
أو `double`.

القدرة من `can_adjust` الخادمية لا من الدور المحلي. قراءة الحالة الواحدة
تكفي شاشة التحرير المستقبلية لأنها تضم القدرة والحقائق المالية؛ قراءة
القدرة المنفصلة بوابة خفيفة قبل الدخول فقط. لا تخبأ سلطة على أنها دائمة.

## الطلب والهوية

`adjustSessionFinancialAmount` نوع أمر مستقل، نطاقه جلسة ولا ينتج كيانًا أو
جلسة أو مقطعًا. الحمولة الدائمة لا تحمل إلا هوية الجلسة، ومراجعات الأساس
الثلاث، والمبلغ المعتمد، والسبب. يولد المغلف `command_id` و`requested_at`
مرة واحدة عند إنشاء النية. السبب يقص قبل الحفظ ويرفض إذا صار فارغًا.

الصفر مبلغ صحيح صالح، والسالب مرفوض. لا actor أو tenant أو حساب مزارع أو
فاتورة أو دفع أو فرق أو قيد أو عملة أو فترة ترحيل في طلب العميل. هذه كلها
يشتقها الخادم.

الحمولة المالية مجمدة بعد الإنشاء وتحفظ في outbox العام. تغيير المبلغ أو
السبب أو مراجعات الأساس نية جديدة ومعرف أمر جديد؛ لا يعدل الصف القديم.
مخطط SQLite الحالي يحفظ النوع والحمولة والوقت والمعرف والحالة والنتيجة،
لذلك لم تضف هجرة SQLite أو تبعية.

## الإرسال والاستعادة

الحفظ المحلي يسبق أول RPC. يسمح بأول كتابة فقط لأمر pending لم يملك دليل
محاولة سابقة، أو بعد فشل محلي قبل بدء RPC مثبت صراحة. بمجرد احتمال خروج
الطلب إلى الشبكة يبقى الأمر `dispatching`، وتقرأ الجولات اللاحقة
`get_session_financial_adjustment_receipt` فقط.

`processing` يحفظ ملاحظة متينة ويبقي `dispatching`. خطأ شبكة أو مصادقة بعد
بدء الكتابة يعامل كغموض إرسال لا كإذن تكرار. `not_found` و`unresolved`
وخطأ الإيصال غير الصالح لا يثبتون أن التنفيذ لم يبدأ، ولا يفوضون إرسالًا
جديدًا.

غموض النقل لا يختلق ملاحظة `processing` خادمية: يبقى حجز المحاولة متينًا
بلا نتيجة خادمية. فشل المصادقة المحلي قبل RPC وحده يسمح بمحاولة إرسال
أولى لاحقة، حتى لو تكرر قبل نجاح المصادقة. تغيّر الحساب أثناء RPC يبطل
تبني الرد ولا يمنح سلطة إعادة الكتابة.

الإيصال قد يحمل رفض الصلاحية أو النتيجة غير المحسومة داخل `result`، وقد
يعيدهما دون نتيجة. يقبل القارئ الشكلين الموثقين ويتحقق من هوية النتيجة
المتداخلة وحالتها. أوقات PostgreSQL تقبل `Z` أو إزاحة صريحة، مع رفض
التواريخ التقويمية غير الصحيحة وحفظ اللحظة بتوقيت UTC.

`accepted` يحفظ النتيجة الحاكمة ويؤكد الأمر. `validation_error` و
`conflict_request` و`conflict_revision` و`financial_review_required` و
`locked` و`permission_denied` تحفظ كنتائج مراجعة نهائية للأمر الأصلي ولا
تعاد تلقائيًا. لا يُعرض SQLSTATE أو JSON خام أو `reason_code` خام للواجهة.

## أثر الجلسة

الأمر المالي ليس start أو stop أو pause أو resume أو انتقال حجز، ولا يدخل
مصنف الأوامر التشغيلية أو حراس منتج الجلسة. `produces=null` و
`aggregateLocalId=null`. `ActiveSessionProjector` يتجاهله صراحة، ولا ينشئ
حالة أو مقطعًا أو مبلغًا محليًا. بعد القبول، الواجهة المستقبلية تعيد قراءة
الحالة والتفصيل والسجل من الخادم بدل تركيب إسقاط مالي.

الجلسة التاريخية اليدوية المكتملة تستخدم العقد نفسه بعد امتلاكها هوية
خادمية ورسمًا حاكمًا. الجلسة الخارجية النشطة تعتمد رفض القدرة الخادمي، ولا
تملك استثناءً محليًا.

## حدود الجولة

لا شاشة أو زر أو نص واجهة مالي نُفذ. لا خادم أو هجرة قاعدة عُدّلت، ولا
تبعية أو lockfile. نموذج المتابعة المصححة مؤجل للواجهة؛ تحفظ النواة الطلب
والنتيجة القديمة بما يكفي لقراءة حالة جديدة، وتأكيد جديد، ثم إنشاء أمر
جديد.
