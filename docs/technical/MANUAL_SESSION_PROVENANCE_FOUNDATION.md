# أساس منشأ الإدخال اليدوي للجلسات

الحالة: تنفيذ ساكن ينتظر تشغيل المالك؛ لا ادعاء RED/GREEN تشغيلي جديد.
لا يفعّل هذا الأساس أي API للإدخال اليدوي أو النقل أو واجهة الهاتف.

## خريطة إعادة الاستخدام

| الحد | افتراضه السابق | التغيير المحدود |
|---|---|---|
| attach_session_to_open_shift | historical_settlement مغلقة فقط تُعزل | عزل النمطين اليدويين المثبتين، وبقاء الفرع القديم |
| enforce_adhoc_duration_vs_next_booking | أمر بدء تشغيلي أو تسوية قديمة مثبتة | استثناء يدوي من إثبات خاص محفوظ، دون راية عميل |
| fill_fuel_transaction | عدم ملء الوردية لوقود التسوية القديمة | تصفير وردية الوقود اليدوي؛ بقية الحساب والتحقق كما هما |
| guard_operational_schedule_write | تمييز التداخل التاريخي بالتسوية القديمة | حماية التداخل في الاتجاهين عند وجود جلسة يدوية، باستخدام الحقائق الفعلية |
| materialize_historical_occurrence | هوية تسوية وإكمال ووقائع رفض قديمة | يحتفظ بكل تحققاته؛ يستدعي نواة إنشاء الجلسة النهائية ومقطعها الأول |
| finalize_session_from_closed_segments | النواة المالية المشتركة | دون تعديل أو نسخ للحساب المالي |

## التخزين وحد الثقة

امتداد ops.operational_occurrences نفسه بقيمتي manual_historical_completed و
manual_external_active، وحقول manual_reason وmanual_notes وmanual_result.
لا خريطة هوية ثانية. tenant/well والفاعل وهوية الأمر وربط الجلسة والأوقات
تبقى في الأعمدة الموجودة. original_request_id يساوي occurrence_command_id
للإدخال اليدوي؛ لا مصدر حجز ولا هوية إكمال/تسوية إرثية.

manual_session_occurrence_mode يطابق الواقعة مع سجل الأمر الخاص تطابق JSON
كاملًا، بما فيه الفاعل والنمط والسبب والملاحظات والحقائق والأوقات.
manual_session_entry_mode هو واجهة الحراس الخاصة؛ دليل يدوي متناقض يفشل
مغلقًا. لا صلاحية تنفيذ أو كتابة للأدوار الهاتفية على هذه الحدود.

عند إدخال الواقعة اليدوية يجب أن يطابق الفاعل auth.uid() وتتحقق صلاحية
session.start، وsession.complete للمنتهية. المدخل العام المستقبلي يحتاج
أيضًا حسم القدرة المستقلة للإدخال اليدوي قبل منحه؛ لا يمنح هذا الأساس
مسارًا عامًا اعتمادًا على صلاحيات البدء وحدها.

النمط والهوية والحقائق والسبب والملاحظات ثابتة. الانتقال الوحيد هو من
materializing إلى accepted بنتيجة يصنعها manual_session_entry_result من
الجلسة ومقطعها والرسم القانوني. يجب إنهاء سجل الأمر بالنتيجة نفسها قبل
اعتماد الواقعة. زناد مؤجل يمنع بقاء واقعة يدوية غير محسومة عند commit.
المعاملات الفاشلة تتراجع بدل حفظ منشأ جزئي.

## حدود النواة الداخلية

begin_terminal_occurrence_materialization ينشئ جلسة مغلقة ومقطعًا أولًا
مسعّرًا بوقت الحدث. يتطلب منشأً خاصًا مثبتًا وقفل المال المملوك مسبقًا.
المدخل المستقبلي يجب أن يملك القفل المالي ثم قفل النطاق التشغيلي قبل
حجز هوية الأمر. التسوية القديمة تحتفظ بالأحداث والمحاصيل وإيصال الإكمال
وباستدعاء finalize_session_from_closed_segments كما كانت.

الغلاف اليدوي المستقبلي سيغلق المقطع ويعالج المحاصيل/الوقود المدعوم
ويستدعي النواة المالية ثم يبني النتيجة ويعتمد الأمر والواقعة في معاملة
واحدة. لا يقبل مبلغًا أو actor أو booking من العميل. لا يتطلب الأصل
اليدوي هوية rejected request أو completion command قديمة.

الحراس لا تتجاوز التداخل: النطاق هو البئر أو المضخة، والفترة المفتوحة
تمتد بلا نهاية حتى الإكمال. النسخ المصححة تُقرأ من effective_session_facts؛
تعديل operational_revision نفسه يظل خاضعًا لإثبات التصحيح الحالي.

بُنيت اختباراته قبل ملف الهجرة ولم ينفذها الوكيل وفق قاعدة تشغيل المالك.

الأساس؛ يظل RED عند سطح APIs العامة إلى أن تنفذ شريحتها لاحقًا.
لذلك لا يُتوقع GREEN للحزمة الكاملة في هذه المرحلة الوسيطة.

يحتاج المالك تطبيق الهجرة الجديدة ثم اختبار الأساس. وللانحدار المشترك:

20261103_operational_start_separation.test.sql و
20261104_operational_start_receipt.test.sql، ثم حزمة DB عند اكتمال APIs.

تعارض الأعمال إلى نتيجة منظمة قابلة للمعالجة دون كشف رموز داخلية للمستخدم.
