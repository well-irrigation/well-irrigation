## ب. ترتيب العمل — دفعة واحدة وPR مستقل لكل هدف

**P0 — بوابة توثيق ق-134 (مغلقة ومدموجة عبر PR #49).** القرار والخطة والمصفوفة والـUX المرجعي موثقة؛ لا يلزم إعادة فتح P0 لهذه الشريحة.

**P1 — ضبط وضع الانتقال وحماية الحدث (أول تنفيذ).** إنشاء حالة تشغيل/إيقاف لكل بئر، ببدء أول جلسة يدويًا، وآلية متسلسلة تمنع إنهاء أو بدء مرتين، وتحتفظ بالمصدر والوقت. اختبارات دائمة: ON/OFF، تغيير الوضع قبل الموعد، عدم الرد، وجود جلسة حرة مانعة، سباق الطلبين، الإغلاق المالي مرة واحدة، التأكد من انتهاء الوقت المحجوز. لا تنفذ الإغلاق الآلي ماليًا قبل مراجعة أثره على التسعير والمقاطع. يُستخدم عقد M113 القائم ولا يُعاد إنشاؤه. أول خطوة قبل تعديل SQL: دراسة أقفال/تسوية الجلسة الموجودة وبيان أصغر تغيير آمن.


**P1-A — إعداد الوضع فقط (Local DB Verified + CI Verified + Merged):** عمود تشغيل `false` افتراضيًا، مراجعة عددية 0 مع CAS، وعقدا القراءة/الكتابة في `api` والعملية المحروسة داخل `ops`، واستدعاء مباشر بلا تجاوز لدورة الأمر. التغيير للمشغل المخوّل فقط؛ القراءة للمالك/المشغل. نجاح المالك: 52 ملفًا، 1103 PASS، وفهرس 891/544/264/49. لا يشغّل الانتقال، ولا يمس سلسلة الحجوزات، و`automation_executor_ready=false`؛ لا Flutter أو Scheduler ولا تحقق Cloud. الاختبارات المستقلة لسباق اتصالين Pending. دُمج عبر PR #51 إلى `main`؛ لا تشغيل فعلي. P1-A-MERGED-PR51-2026-10-04.

**P1-B — نواة الانتقال الذرية وإثبات التزامن (Local DB Verified + Concurrency Proof Verified):** إضافة دالة `ops.execute_booking_transition(uuid, bigint, uuid)` التي تجمع إغلاق الجلسة المحجوزة عند حدها الموثوق (748/762) بتفويض `ops.complete_irrigation_session` وبدء الحجز التالي المستحق بتفويض `ops.start_booking_session_core` في معاملة ذرية واحدة. الحراس: هوية حقيقية، إعداد ON مقفول، سلسلة active مسلّحة، زمن 748، الحجز التالي مستحق، CAS على نسخة السلسلة، دورة أمر `sync`، وترتيب أقفال settings → session → chain → booking → pump. إثبات `db:test`: 52 ملفًا، 1119 PASS (منها 227 PASS لاختبار M113 بـ 16 تحققًا لكتلة PB)، صفر فشل/خطأ، وفهرس 891/544/265/49. إثبات التزامن باتصالين مستقلين بـ PostgreSQL عبر `scripts/p1b_transition_concurrency_proof.py`: السيناريو أ أثبت منع التنفيذ المزدوج بحجب الاتصال الثاني على أقفال الأول ثم رفضه نظيفًا (`current_not_reached_operational_end`) دون جلسة ثانية أو رسوم مكررة وبدفتر أوامر نظيف؛ والسيناريو ب أثبت الـ idempotency لنفس command_id بحجب الاتصال الثاني على قيد فريدية سجل الأمر ثم إعادة الرد المخزن حرفيًا وسجل أمر واحد. النواة **غير مفعلة إنتاجيًا** ومسحوبة الصلاحيات بالكامل (`REVOKE ALL FROM public, anon, authenticated, service_role`) وبلا أي كشف في `api` وبلا مجدول زمني أو واجهة Flutter. **لا يوجد قرار جديد مطلوب**؛ ق-134 والثوابت 748–753 و761–764 كافية ومحكمة.

**P2 — المُشغّل الزمني المستقل وقبول الهاتف.** **Phase 2B cloud proof منجزة ومندمجة عبر PR #58**: Candidate A (`Supabase Cron → Edge Adapter → DB execution`) أثبتت الجدولة، الهوية التقنية، إعادة التحقق الذري، التزامن، إعادة المحاولة، الإيقاف والمراقبة والتنظيف؛ لا Cron دائم ولا Production activation، وq-137 غير معتمد بعد. المتبقي قبل إغلاق قبول P2 هو الهاتف: Online-first لجدول اليوم/ON-OFF/البدء اليدوي الأول، ثم Offline booking cache/local transition/missed-start/notifications/readiness وقبول Android فعلي. أول بدء يبقى يدويًا ولا يبدأ الفائت متأخرًا بصمت.

**P3 — تأخير الجدول.** تمديد محدد: تُضاف المدة وحسابها للجلسة الحالية وتُزاح بدايات/نهايات التالية، مع الحفاظ على مدتها. انتظار مفتوح: لا تحريك نهائي حتى إنهائه؛ احتساب السقي الإضافي ما عدا التوقفات؛ عند الإنهاء تتحرك الحجوزات وتُستأنف الأتمتة. تنبيه قبل الانتهاء 5 دقائق قابل للضبط؛ تذكير بعد تأخير 5 دقائق ثم كل 15 دقيقة، وإبلاغ المالك بعد 30 دقيقة. الإيقاف المبكر يحتفظ بقرار run_now/wait. لا تقديم تلقائي عند إلغاء حجز. التعارض/العبور لليوم التالي يعرض قرارًا للمشغّل مع معاينة الأثر؛ لا نقل صامت لحقوق المزارعين.

**P4 — الهاتف والأعمال دون اتصال.** هاتف مشغّل واحد لكل بئر في V1؛ تخزين الحجوزات المؤكدة والجاهزية على الهاتف وإظهار حالة المزامنة. انتقال محلي حيث يتاح توقيت النظام وصلاحياته، وإشعار محلي دون إنترنت؛ مزامنة تلقائية عند عودة الاتصال دون فتح واجهة عندما يسمح Android؛ لا ضمان في Force Stop/قيود البطارية، مع تحذير/إرشاد دائم. إذا انطفأ الهاتف وفاتت انتقالات لم ينفذها مصدر موثوق، يعرض تأكيدًا واحدًا أو تصحيحًا جماعيًا بدل كتابة بدايات وهمية. أولوية حسم خادمية تمنع ازدواج التنفيذ لو نفذ الخادم/الهاتف معًا.

**P5 — التصحيح والمحاسبة.** مسار منفصل لتصحيح جلسة مغلقة أو مجموعة مترابطة: سبب إلزامي، الأصل والتاريخ والمصحح، أثر كل جلسة، فروق محاسبية فورية بعد قبول الأمر الموثوق، دون تغيير سند القبض أو محو التسوية السابقة. لا تغير مواعيد/مبالغ غير المتأثرين بالتخمين. المشغّل يعمل Offline ويُظهر `pending`؛ تصحيحه غير نافذ على الخادم حتى القبول. تصحيح المالك للتاريخ المستقر مسموح دون اتصال المشغّل؛ تعديلان متعارضان يبقيان للمراجعة وحسم المالك مع سبب.

**P6 — الطوارئ والطاقة.** «توقف طارئ» يوقف العد المفوتر وانتقالات السلسلة ويحفظ الدقائق المتبقية؛ عند الاستئناف يختار المشغّل الاستكمال أو الإنهاء الفعلي مع السبب. عطل طويل مع حجوزات متعارضة: تعرض للمشغّل بدائل حفظ موعد اليوم التالي، أو إعطاء أولوية للمتضررين، أو ترتيب يدوي، أو تأجيل محدد، مع معاينة كاملة ومنع الحذف/التداخل الصامت. انتقال الشمس إلى البديل المحدد حالة تشغيل ومحاسبة فقط؛ عند تعذر المصدر، يتخذ المشغّل إجراء استثنائيًا. تبديل ديزل البئر/المزارع يحفظ مقاطع منفصلة ولا يضيف Fuel Charge جديدًا.

**P7 — تحكم المالك والإشعارات.** تحكم المالك المباشر في تشغيل البئر يتطلب بيانات متطابقة واستلامًا وتنفيذًا موثقًا من هاتف المشغّل بلا أوامر معلقة؛ لا تكفي مزامنة عمرها 5 أو 10 دقائق. تنبيه عمر 5 دقائق وتصعيد 10 دقائق للعرض فقط. عند انفصال الهاتف يُحفظ طلب مؤجل يُراجع لاحقًا، ولا يُنفذ تلقائيًا إذا تغيرت الحالة. تعديل تاريخ مستقر منفصل. تنبيهات مشغّل محلية، المالك/غيره عبر الاتصال حين يتاح، وسجل إرسال/وصول دون نجاح كاذب؛ إشعار فوري للمالك بأي تصحيح يقبله النظام مع تخزين الإشعار حتى الاتصال.

**P8 — تكامل وقبول ونشر منفصل.** اختبارات DB دائمة لكل هجرة جديدة، Flutter analyze/test، اختبار Android حقيقي: اتصال متقطع، انطفاء الهاتف، Force Stop، منع الإشعارات، سباق جهاز/خادم، تسوية مدفوعة وتصحيحها، عبور اليوم، مصدر طاقة بديل. `c:state` ثم `c:db` و`c:app` بحسب نطاق التغيير، CI قبل وبعد الدمج. فحص الحضور السحابي والفروقات وترحيل production بخطة واعتماد مستقل. M114 وتنفيذ سعر ديزل المعلوماتي ضمن Phase B، لا يغلق بمجرد نجاح P8.

## ج. اشتراطات لا تُسقط

- `booking ≠ session`؛ أول بدء صريح. الحجز الحر والعابر لا يُغلقان بآلة الحجوزات.
- لا تنفيذ آلي على حجز ناقص/غير مؤكد، ولا جلستين مفتوحتين على البئر.
- لا تلاعب بأوقات حدث لم يقع؛ يميَّز تسجيل الجدول الآلي عن إثبات الميدان والتصحيح اللاحق.
- مدة الحجز المخططة ثابتة للمزارع التالي ما لم يتخذ المستخدم قرارًا صريحًا؛ نهاية الجلسة الفعلية والتسوية المالية الحقيقة المنفذة لا زمنًا مخترعًا.
- تُحفظ أوامر Offline والسبب والمراجعة والإيصالات ولا تُستبدل بنسخ مصطنعة.
- ينفذ كل جزء على فرع PR مستقل؛ لا DB/cloud/Git local agent؛ بوابة المالك وفحوص CI قبل الدمج.
